# 📄💬 PDF RAG WebSocket Chat

A real-time chat that answers questions about the contents of a PDF using **RAG**
(Retrieval Augmented Generation) — chat with your documents over a live websocket
connection. Every part of the pipeline runs **free and 100% local**: no paid APIs, no
cloud services, no API keys required.

This is a practice/learning project built as the second part of a websockets class
exercise: first a plain real-time chat, then extended into a full RAG pipeline.

## ✨ Features

- 📑 Extracts text from any PDF and splits it into overlapping chunks
- 🔢 Counts tokens per chunk to keep context windows under control
- 🧠 Generates multilingual embeddings locally (no API calls)
- 🗄️ Stores and searches vectors in an embedded Qdrant instance (no Docker needed)
- 🔌 Real-time chat over a native websocket connection
- 🤖 Answers are generated by a local LLM (Ollama) grounded in the retrieved chunks
- 🌑 Dark-themed Angular frontend to chat from the browser

## 🧰 Tech stack

| Layer | Technology |
|---|---|
| PDF text extraction | [PyMuPDF](https://pymupdf.readthedocs.io/) |
| Chunking & token counting | Custom splitter + [tiktoken](https://github.com/openai/tiktoken) |
| Embeddings | [sentence-transformers](https://www.sbert.net/) (multilingual model) |
| Vector database | [Qdrant](https://qdrant.tech/) (embedded, local mode) |
| LLM inference | [Ollama](https://ollama.com/) (`llama3.2`, local) |
| Backend server | Python + [`websockets`](https://websockets.readthedocs.io/) |
| Frontend | [Angular](https://angular.dev/) 21 + TypeScript + SCSS |

## 🏗️ How it works

**Phase 1 — Ingestion** (`backend/ingest.py`, run once per PDF):

```
PDF → extract text → chunk + count tokens → generate embeddings → store in Qdrant
```

**Phase 2 — Chat** (`backend/server.py`, runs continuously):

```
User asks a question over websocket
  → embed the question (same model as ingestion)
  → search Qdrant for the most relevant chunks
  → build a prompt (retrieved chunks + question)
  → ask the local Ollama model
  → stream the answer back over the websocket
```

## 🚀 Quick start

1. **Backend** — follow [`backend/README.md`](backend/README.md): install dependencies,
   ingest your PDF once, then start `python server.py`.
2. **Frontend** — follow [`frontend/README.md`](frontend/README.md): `npm install`, then
   `npx ng serve`.
3. Open `http://localhost:4200` and start chatting with your PDF. 🎉

> ⏱️ **Heads up:** answers take roughly 30-90 seconds when running Ollama on CPU only (no
> GPU). That's expected, not a stuck connection — see `backend/README.md` for details.

## 💡 Key decisions worth knowing

- **PyMuPDF over pypdf/pdfplumber** for text extraction — ~1600x faster than pdfplumber on
  a 1608-page test PDF, at the cost of occasional cosmetic word-spacing noise.
- **A multilingual embedding model**, not the default English-centric one — the initial
  model produced backwards semantic similarity on Spanish text.
- **The RAG call runs in a worker thread** (`asyncio.to_thread`) inside the websocket
  handler, so a slow LLM response never blocks the event loop's keepalive pings.

See [`backend/README.md`](backend/README.md) and [`frontend/README.md`](frontend/README.md)
for the full write-up of each decision.
